# HTML 可视化编辑器

在浏览器中直接编辑本机 HTML 页面：改文字、调样式、拖动组件，并保存回原 HTML。适合静态网页、产品原型和演示页面，也能配合 AI 编程工具一起使用。

源码公开，采用 [非商业源码许可协议](LICENSE)，**禁止商业使用**。运行在你的电脑上，无需注册账号，无需安装运行依赖。

## 三步开始使用

1. 安装 [Node.js](https://nodejs.org/)，需要 **22 或更高版本**。
2. 点击仓库右上方 **Code → Download ZIP**，解压到电脑上。
3. 在解压后的文件夹中打开终端，运行：

   ```bash
   npm start
   ```

打开浏览器访问 **[http://127.0.0.1:4174/editor/editor.html](http://127.0.0.1:4174/editor/editor.html)**。使用期间保持终端窗口开着；按 Ctrl + C 停止服务。

**Mac 用户**也可在安装 Node.js 后双击 `快捷启动.command`。如果文件不可执行，可在终端运行 `chmod +x 快捷启动.command`，或直接使用上面的启动命令。

**Windows / Linux 用户**使用 `npm start`。Windows 可在文件夹地址栏输入 `cmd` 回车，再输入启动命令。

不需要运行 `npm install`。也可以用 `node dev-server.mjs --port 4174` 启动。

## 第一次体验

点击编辑器顶部的“打开项目文件夹”，选择仓库里的 **`examples/demo`** 文件夹，再切换到“编辑”模式，就能试着修改示例页面。

macOS 支持系统文件夹选择器；Windows / Linux 请在弹窗中粘贴文件夹的完整路径。

使用自己的页面时，选择包含 HTML、CSS、JS、图片等资源的项目根目录，然后在顶部“页面”菜单切换文件。更多操作见 [使用指南](EDITOR-QUICKSTART.md)。

## 可以做什么

- 通过“迭代需求”管理版本迭代，结合原型、文字、图片和录音讨论需求，生成可编辑的 5W2H 文档并复制到飞书。
- 点击选择元素，双击改文字；调整字体、颜色、圆角、透明度、尺寸和留白。
- 拖动、跨容器移动、对齐吸附；调整横向、纵向与网格排列。
- 新增文字、按钮、卡片、容器、矩形、圆形和本地图片；复制、删除、多选、隐藏与锁定。
- 撤销 / 重做，浏览器自动保存草稿。
- 保存回原 HTML，检查外部修改冲突，并自动备份源码。
- 预览历史版本、恢复源码、上下对比版本。
- 导出调整 JSON 或包含本地资源的项目 ZIP。

## 保存与分享

### 迭代需求文档

项目栏点击 **“迭代需求”**，新建迭代，填写名称、场景和范围。可选择全部页面与功能、指定页面（页面内部范围写在补充说明里），或边讨论边确定。支持先保存为“待开始”，再开始；进行中的迭代可以结束为“已完成”，之后重新打开或基于完成版本新建下一轮。

工作区复用现有 AI 连接。打开工作区或切换迭代只读取已保存内容。首次开始迭代、发送消息或点击“分析原型”时，才检查关联页面、CSS/JS、逻辑标注及资料变化并分析；讨论、回答整理和原型分析中的AI正文变更统一生成待确认修改，接受前保留原文。建议区的“接受并更新需求文档”只更新正文，不修改原型；已有原型建议也按补充需求写入 How 章节。分析使用已保存文件，请先处理未保存的原型草稿。

文档按整次迭代说明 Why/What/When/Who/Where，在 How 中展开各功能板块，验收标准对应功能点。可以直接编辑 Markdown 正文、查看修改记录、撤销，以及复制全文或章节到飞书。富文本复制包含标题、列表和表格；飞书的最终粘贴样式由其编辑器决定。

支持 TXT/Markdown、上传或粘贴图片、上传已有录音。录音转写复用当前接口的 `/audio/transcriptions`，转写模型默认 `whisper-1`，可自行修改；接口不支持时可手动填写文字稿。生成需求与源码需要当前模型支持 Chat Completions，图片需视觉能力。迭代、资料和历史保存在编辑器本机 `.editor-workspaces/requirements/`，不会混入原型导出的源码 ZIP，也不会直接上传到飞书。开始分析或转写时，相关资料会发送至你配置的模型服务。

`npm run test:requirements` 使用本地模拟模型验证需求流程，不调用真实模型服务。

编辑时先自动保存到浏览器草稿；点击 **“保存到项目”** 才会写入你选择的原 HTML。写入前会检查冲突，并备份 HTML、项目 CSS/JS 和草稿。

可用 **⌘/Ctrl+S** 保存，状态栏会显示实际写入的本地 HTML 完整路径。浏览器草稿、AI 待办与已写入源码是不同状态；有待办时只算部分保存，需 AI 自动检查并保存剩余修改后才算完整写入。

普通静态项目可通过 **“保存并导出开发源码 ZIP”** 交付。导出前先保存当前页面，并检查项目各页面是否仍有持久化待办；有冲突、保存失败或待办时不生成源码包。ZIP 包含磁盘上的 HTML、CSS、JS 与本地资源，不再临时注入编辑草稿伪装成源码。接收者解压后用本地 HTTP 服务打开；远程资源和后端接口仍需自行提供。多页面项目需逐页保存；其他页面或浏览器里的未保存草稿不包含在源码包中。动态元素已保存到 HTML 内的恢复记录仍会保留。

点击 **导出 → 局域网分享**，保存后生成同一 Wi-Fi / 局域网可打开的浏览链接。“复制链接”后发给同事即可查看页面和本地资源；分享页沿用当前桌面、平板或手机画布的宽度，并按查看者窗口整体缩放，保持拖动后的布局；支持正常页面交互，不提供编辑器或文件写入接口。保存到项目后，同一个分享链接会自动同步，已打开的分享页面约 2 秒内自动刷新；链接没有时间限制，分享记录与端口保存在本机，服务重启后自动恢复原链接；“停止分享”才会撤销链接。电脑休眠、关机或服务未运行时暂时无法访问，恢复运行后可继续使用；局域网 IP 改变时需复制当前网络地址。多个网卡会提供多个地址，可切换使用。

编辑器自身需要本地 Node.js 服务来读取和保存文件。GitHub 仓库用于下载和分享，不能通过 GitHub Pages 完整运行这个编辑器。

## 支持范围

支持普通静态 HTML 项目。React / Vue 等需要构建的源码项目，请先生成静态页面。打开页面后会检查保存方式，选中元素可查看具体说明。静态元素直接写回 HTML；具有唯一、固定 `id` 或 `data-ve-node` 的动态元素可将修改保存到 HTML 内的调整记录，页面打开时自动恢复。页面内脚本模板中可唯一定位的固定文字（例如模板中的 `<span>今日应收</span>`）会直接修改生成模板，保留交互标识，刷新和重新生成后仍生效。重复文字、插值、外部脚本等无法明确定位的情况，以及无法直接保存的结构或容器修改，会保留预览并进入 AI 待办。普通修改先保存，AI 基于最新源码修改生成逻辑；自动检查通过后备份并写入。复制组件不会复制通过 JavaScript 绑定的事件。

服务默认只监听 `127.0.0.1`，用于本机编辑。浏览器里的被编辑页面仍会运行自身脚本，请选择你信任的项目。

本机配置 `editor-config.json`、最近项目路径、编辑记录和历史备份都已加入 Git 忽略规则。

### 安全分享编辑器源码

不要直接压缩整个本地编辑器文件夹：Git 忽略规则不能阻止系统压缩工具把本机 API 密钥和项目路径打进 ZIP。

分享编辑器自身源码请使用 GitHub 的 **Code → Download ZIP**，或在仓库目录运行 `npm run share:source`。后者生成 `html-editor-source.zip`，只打包最近一次 Git 提交中的源码，不包含未提交修改和 Git 历史，并额外排除本机配置、环境文件（保留 `.env.example`）、草稿、历史备份、依赖和压缩包，即使这些私有文件被强制提交也不会打包。若源码包含当前本机保存的 API 密钥或常见密钥格式，立即停止，不生成 ZIP，也不显示密钥内容。已有同名 ZIP 不会被覆盖。

需要指定输出位置时运行 `npm run share:source -- /完整路径/源码.zip`。该检查无法识别所有供应商密钥及其他隐私；分享前仍需检查源码，尤其不要将密钥写入示例、截图或文档。此命令只保护编辑器源码分享，不代表任意项目 ZIP 都经过隐私检查。

### AI 对话修改界面

点击左侧工具栏“AI 对话”，直接用自然语言描述当前页面的文字、样式、布局或交互修改，无需先创建待办。可引用选中元素或框选目标区域，并上传/粘贴截图，模型同时接收图片、元素定位和相关源码（截图需支持图片输入的模型）。普通草稿先保存，AI 基于最新源码和最近对话生成局部修改，并固定遵守本编辑器的完整兼容要求。点击“发送并修改”后，编辑器自动检查、备份、写入源码并刷新主画布，无需再次确认。历史对话默认折叠，按需展开查看；对话和失败输入按页面保留在当前浏览器，可连续提出下一轮要求。具体操作见 [使用指南](EDITOR-QUICKSTART.md)。

### AI 接口设置

点击顶部“AI 待办”，展开“模型连接”，填写兼容 Chat Completions 的自定义接口地址（支持 HTTP/HTTPS）和 API 密钥。密钥也可以通过可选的环境变量设置。点击“加载模型”从该接口的 `/models` 获取模型选项，可搜索、用方向键和 Enter 选择；接口不支持模型列表时可手动填写模型名称。例如接口地址可以填写服务商的 API 基础地址（通常以 `/v1` 结尾），也可填写完整的 `/chat/completions` 地址。

点击“测试连接”即可对当前表单中的接口和模型发起一次简短请求，查看连接结果、响应耗时及错误原因。测试不需要 AI 待办，不会保存连接设置或修改项目源码。

在启动服务的终端中设置该环境变量，然后启动或重启编辑器。不要将密钥填进模型名、接口地址或环境变量名，也不要提交到 Git。HTTP 会明文传输密钥，建议使用 HTTPS。配置保存在本机忽略目录 `.editor-workspaces/ai-config.json`；直接填写的密钥保存在仅本机用户可读写的配置文件中，接口不回传；也可由服务端从环境变量读取。

保存时，可直接写入的字段先保存并备份，其余字段持久保留在“AI 待办”。配置完成后，编辑器自动调用接口。模型会收到当前页面及项目 CSS/JS 源码、剩余修改要求。源码请求限制为 2MB；模型返回局部精确替换片段，无需回传整个大型页面。服务端仅合并现有文件中唯一匹配的片段，找不到或重复匹配时拒绝修改；仍兼容完整文件返回。空修改会显示模型给出的原因，输出被截断时单独提示。生成后自动进行页面效果检查，通过后备份并写入本地文件。

页面效果验证同时加载生成时的原始源码快照作为基线。原页面已有的脚本或资源错误会显示警告，不再被误判为 AI 修改失败；本次新增的脚本错误、资源加载失败或未生效的修改仍会阻止写入，并显示具体错误或资源地址。

编辑器在后台检查 JS 文件语法和待办对应的文字、样式、位置等页面效果，通过后自动备份、写入并清除已完成的待办，刷新主画布。源码差异可展开“查看本次源码修改”查看。自动检查覆盖当前加载状态，复杂交互仍需在主画布中检查。API 错误、效果检查失败或生成后源码发生变化时不会写入 AI 结果，待办继续保留；可重新发送。

接口协议参见 [Chat Completions 官方文档](https://developers.openai.com/api/reference/resources/chat)。尚未对任意服务商做兼容性保证。

逐题补充理解：在需求讨论中点击「补充理解」，设置 1–20 道问题和每题最多 0–8 个选项。选项不合适时可手写，也可以跳过；点击下一题保存当前回答，重新进入可继续。全部完成后点击「整理到需求草稿」，统一更新 5W2H 文档。生成问题和整理回答各调用一次 AI，逐题保存不调用 AI。跳过的事项保留待确认。

开始迭代分析后，直接逐个询问已有待回答问题，无需再次生成问题。保存后进入下一题，可以跳过或稍后继续；重新打开工作区会继续未完成的问题。全部回答后统一整理到需求文档。右侧「待回答」作为问题目录，「已确认回答」用于核对和修改答案。

原型分析生成的改进卡片集中放在「需求建议」页。认可时点击「采纳建议，写入需求文档」，暂时不确定时点击「暂不采纳」。采纳只更新需求文档，原型页面需要另行修改。

在「待补充」Tab 可逐项点击「补充回答」；在「已确认回答」Tab 可点击「修改答案」，重新选择选项或手写。保存只更新回答记录，并保留旧答案；点击「整理到需求文档」再统一更新 5W2H 草稿，不修改原型。待整理状态在刷新后保留。

How 按子功能和指标分别说明数据对象、字段、范围、计算、输入保存、异常和验收；每个未明确规则对应独立待回答问题，问题数取决于实际缺口。分析会读取项目根目录及 docs 下名称含需求、交接、开发交付、requirements 或 Meeting-Summary 的 Markdown 作为带文件名的参考（不自动读取归档/计划），当前明确回答优先于历史冲突。问题可分批回答，点击「用已答内容生成修改预览」后继续尚未回答的问题。

「逻辑冲突」页单独列出原型、历史资料和当前需求的不同说法及来源。填写解释后点击「保存解释，让 AI 更新文档」，解释先持久化，再调用AI更新完整需求文档；更新成功后移入已处理记录。AI失败时解释仍保留，可重试；修改已处理冲突的解释可再次更新。尚无相反说法的未知规则仍在待回答。

AI更新需求采用“先预览、再确认”：在「待确认修改」查看涉及章节及新增/删除内容；点击「接受修改，更新正文」才写入，拒绝则保留原文和回答，填写意见可重新生成候选。回答同步、冲突处理状态也在接受后更新。正文或回答已变化时，旧预览不能覆盖新内容，须重新生成。已接受修改可通过文档撤销恢复。


需求交付检查：工作区顶部会根据待确认修改、逻辑冲突、已答未写入及待回答状态推荐下一步。需求文档工具栏下的「开发交付检查」默认折叠，列出章节和逐功能说明缺口；这只是文字结构检查，不表示业务规则已确认。点击「让 AI 检查交付完整性」会重新审查当前原型与文档，即使原型没有变化；AI 文档修改仍先生成预览。预览同时列出接受后待回答目录的新增和移除，便于核对。通过「复制交付稿（含未定案清单）」复制当前正文及待回答、冲突、已答未写入、待确认修改的附录；未接受的候选正文不进入交付稿。
